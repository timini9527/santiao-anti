# 朋友圈冒烟测试优化说明

## 优化目标

朋友圈冒烟集只覆盖“每日快速判断核心链路是否可用”的场景，避免把完整回归、边界组合和高耗时媒体场景全部塞进冒烟，导致执行慢、失败定位粗、环境依赖过重。

## 本次优化内容

| 类型 | 调整项 | 目的 |
|---|---|---|
| 新增用例 | 空内容发布拦截 | 覆盖发布入口的 P0 负向校验，防止空内容被误发布 |
| 增强校验 | 单图发布后校验首条动态包含图片节点 | 避免只发出文字也被误判为图片发布成功 |
| 增强校验 | 视频发布后校验首条动态包含视频节点 | 避免只发出文字也被误判为视频发布成功 |
| 稳定性 | 修正 `is_moment_contains_media` 的索引参数和空节点保护 | 避免媒体校验误查首条或空元素报错 |

## 当前冒烟覆盖范围

| 用例 | 覆盖能力 | 保留原因 |
|---|---|---|
| `test_smoke_enter_and_refresh` | 进入朋友圈、刷新信息流 | 最基础入口与页面健康检查 |
| `test_smoke_post_text_moment` | 纯文本发布、列表展示、删除清理 | 最高频发布链路 |
| `test_smoke_empty_text_moment_blocked` | 空内容发布拦截 | 轻量 P0 负向校验 |
| `test_smoke_post_image_moment` | 单图发布、媒体节点校验、删除清理 | 核心媒体发布链路 |
| `test_smoke_post_video_moment` | 单视频发布、媒体节点校验、删除清理 | 如视频链路耗时过高，可降级到媒体冒烟集 |
| `test_smoke_cancel_post_moment_dialog` | 编辑页返回、放弃编辑确认 | 防止编辑页状态卡住影响后续链路 |
| `test_smoke_interaction_flow` | 点赞、评论、删除评论、取消点赞 | 覆盖核心互动闭环 |

## 不建议放入冒烟的场景

| 场景 | 建议归属 | 原因 |
|---|---|---|
| 多图 9 张发布、追加图片 | 回归测试 | 耗时高，属于边界组合 |
| 图视频混选拦截 | 回归测试 | 属于媒体选择规则，不是每日冒烟必需 |
| 超长文本、敏感词、emoji 全量参数化 | 回归测试 | 数据组合多，失败定位应放在专项用例 |
| 评论敏感词、评论超长 | 回归测试 | 交互专项覆盖即可 |
| 上滑加载到底部 | 回归测试或稳定性测试 | 执行时间长，环境数据依赖大 |

## 后续维护原则

1. 冒烟用例优先覆盖入口、发布、互动、清理闭环。
2. 每条冒烟尽量能在失败时定位到一个明确能力点。
3. 媒体类冒烟必须校验媒体节点，不能只校验正文。
4. 新增边界、风控、权限、复杂媒体组合时，优先放到 `tests/moments` 回归集。
5. 如果视频上传稳定性影响每日冒烟，可以将 `test_smoke_post_video_moment` 标记为单独媒体冒烟任务。
