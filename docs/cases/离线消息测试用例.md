# 三条 IM 离线消息测试用例

## 1. 测试范围与执行约定

覆盖接收端离线期间产生的单聊、群聊消息，以及恢复连接后的同步、展示和状态更新。系统通知单独判定。Android、iOS、鸿蒙按各自支持能力执行，Web 在目标版本支持对应能力时纳入。

| 项目 | 执行约定 |
| --- | --- |
| 测试账号 | A 为在线发送方，B 为离线接收方，C 为在线对照方或第三账号。A、B 是正常好友。群聊使用包含 A、B、C 的测试群。多端场景用 B1、B2 表示同一账号的两台设备。 |
| 离线前置 | 先确认 B 能正常收消息并记录未读基线。全断网用例确认 B 的设备无网络。测试系统推送时，保持 B 的设备联网，并通过测试环境确认 B 的 IM 实时连接不可用。后台、锁屏和进程结束分别记录。 |
| 默认流程 | ① 让 B 进入指定离线状态。② A 发送测试消息，记录发送结果。③ B 按用例要求恢复网络、连接或登录。④ 检查会话列表、聊天详情和消息内容。需要验证未读时，先检查列表，再进入会话。 |
| 核对数据 | 每轮使用唯一批次标记和可区分的媒体样本。以发送成功的消息清单或可查的服务端消息记录为准，核对接收方、会话、发送人、类型、内容、条数和会话内顺序。可取得消息 ID 时按 ID 核对。 |
| 验收口径 | 执行前记录各端能力、通知和未读规则、历史可见范围、分页与保留策略、媒体限制和时延目标。未确认且影响判定的规则标记为待确认，平台明确不支持的组合标记为不适用。 |
| 优先级 | P0 覆盖核心消息补收、数据完整性和账号隔离。P1 覆盖扩展消息、通知策略和常见异常。P2 覆盖低频边界和专项验证。 |

## 2. 按消息类型验证离线补收

每行在支持该类型的**单聊和群聊**分别执行。按默认流程补收后，先核对消息是否进入正确会话，再按表格检查内容和可用性。验证媒体时，B 使用未缓存的样本。

| 编号 | 优先级 | 类型 / 场景 | 测试数据与操作 | 预期结果 |
| --- | --- | --- | --- | --- |
| IM-OFF-M01 | P0 | 文本 | 分别发送中文、英文、数字、换行、混合字符和接近长度上限的合法文本。B 补收后查看正文。 | 正文与发送内容一致，无乱码、缺行或意外截断。列表摘要按产品规则展示。 |
| IM-OFF-M02 | P0 | 普通表情 | 分别发送 App 内置表情、系统 Emoji、组合 Emoji 和文字混排。 | 表情与文本顺序正确，组合字符不被拆开，无乱码。 |
| IM-OFF-M03 | P1 | 表情包 | 分别发送静态、动态、商店和收藏表情。增加 B 未添加该表情包的场景。 | 展示对应表情，动态资源按设计播放。B 未添加表情包时按产品策略展示或降级，会话可正常浏览。 |
| IM-OFF-M04 | P0 | 图片 | 分别发送普通图片、原图、长图和多张图片。B 打开缩略图及大图。 | 图片张数、内容、顺序与发送方式一致。普通图能预览，原图按规则加载，批量图片不漏张、不串图。 |
| IM-OFF-M05 | P1 | GIF 动图 | 发送产品支持的 GIF，并按配置验证大小上限附近的合法样本。B 进入会话查看。 | 按 GIF 对应规则展示和播放，帧内容正确。无法播放时按已定义的降级规则展示。 |
| IM-OFF-M06 | P0 | 视频 | 分别发送相册视频和现场录制视频。B 查看封面，播放并拖动进度。 | 封面、方向、时长对应原视频。视频可正常播放，声音与画面正确，拖动后能从对应位置继续播放。 |
| IM-OFF-M07 | P0 | 语音 | 发送短语音和接近时长上限的合法语音。B 查看语音时长并播放。 | 条数、时长、顺序和音频内容正确。未听和已听状态按产品规则切换。 |
| IM-OFF-M08 | P0 | 文件 | 发送 PDF、文档、表格、音频、压缩包等受支持文件。覆盖同名不同内容、中文长文件名和合法大文件。B 下载并打开。 | 文件名、类型和大小正确。下载内容可用，支持原样下载的文件可用哈希核对。两个同名文件不会互相替换。 |
| IM-OFF-M09 | P1 | 链接 | 发送带路径和查询参数的合法链接。版本支持链接卡片时，另发一张有标题和封面的卡片。 | 链接文本和跳转目标正确。卡片摘要与原链接匹配，外部页面无法访问时聊天列表仍可正常浏览。 |
| IM-OFF-M10 | P1 | 位置 | 发送一个已知地点。B 查看位置卡片，打开地图并核对目的地。 | 地址、地点名称和地图落点正确。地图权限受限或服务不可用时，按产品设计提示或降级。 |
| IM-OFF-M11 | P1 | 个人名片 | A 分享测试联系人 C 的名片。B 补收后打开名片。 | 名片身份和目标资料页对应 C。查看详情或添加入口符合 B 与 C 的关系和权限。 |
| IM-OFF-M12 | P1 | 群名片 | A 分享目标测试群的名片。分别使用已入群和未入群的 B 查看。 | 群名片指向正确群。查看、申请加入或拒绝访问按 B 的实际权限处理。 |
| IM-OFF-M13 | P1 | 引用回复 | 分别引用 B 已缓存、未缓存和已撤回的原消息，支持时覆盖文本和媒体引用。 | 引用和回复配对正确。原消息可见时定位到正确条目，失效时按设计展示占位或提示。 |
| IM-OFF-M14 | P1 | 逐条转发 | 选择多条受支持的文本、图片或文件，逐条转发给离线的 B。 | 转发条数、会话内顺序和各条内容正确，每条媒体可独立打开。 |
| IM-OFF-M15 | P1 | 合并转发 | 把文本、图片和文件合并为聊天记录卡片。B 打开详情并检查子消息。 | 外层只出现一张卡片。内部条数、原发送人、内容和顺序正确，支持查看的子消息可打开。 |
| IM-OFF-M16 | P0 | 群 `@` 消息 | 分别发送普通群消息、`@B`、`@C` 和有权限发送的 `@所有人`。B 上线先看列表，再查看对应消息。 | B 收到其有权查看的群消息。只有命中 B 的消息按规则产生 `@` 提醒，定位和提醒消除符合设计。 |
| IM-OFF-M17 | P1 | 进群邀请 | B 离线时发出进群邀请，分别在邀请有效和失效后恢复。 | 邀请记录对应正确群和邀请人。有效邀请可按规则处理，失效邀请有明确状态。 |
| IM-OFF-M18 | P1 | 群公告与群系统消息 | 在 B 离线期间分别发布公告、邀请成员、移除成员。群助手启用时增加欢迎语和定时消息。 | B 按权限和会话规则看到对应公告或系统消息，事件对象正确。消息、公告状态和提示不会重复显示。 |
| IM-OFF-M19 | P1 | 语音和视频通话记录 | B 完全断网时，A 分别发起语音和视频呼叫，并在 B 恢复前结束。 | 对支持补收的记录，B 会话显示正确的呼叫类型和终态。已结束呼叫不会在恢复后作为新来电响铃。 |

红包、转账、实时位置等能力由目标版本确认。确认存在后，按真实业务补齐正常接收、失效和权限用例。

## 3. 离线状态与恢复入口

| 编号 | 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- | --- |
| IM-OFF-R01 | P0 | 前台断网再恢复 | B 停在目标聊天页，完全断网。A 发送多条文本及媒体。B 恢复网络并留在原页。 | 消息在规定时限内进入当前聊天，顺序正确。退出会话后列表摘要与聊天详情一致。 |
| IM-OFF-R02 | P0 | 后台再回前台 | B 退到后台，确认 IM 实时连接已断。A 发送消息。B 从桌面手动返回。 | App 恢复后补齐未同步消息，列表和详情一致。未点击通知也能完成补收。 |
| IM-OFF-R03 | P1 | 锁屏后解锁 | B 锁屏并确认进入待测离线状态。A 发送消息。B 解锁并打开 App。 | 消息完整补收，锁屏期间的系统通知按独立用例判定。 |
| IM-OFF-R04 | P0 | 进程结束后冷启动 | 分别用测试平台支持的方式结束 App 或模拟系统回收。A 发送消息。B 手动冷启动。 | 会话可正常恢复，离线消息无漏收、无重复。记录实际进程结束方式。 |
| IM-OFF-R05 | P1 | 退出后重新登录 | B 主动退出账号。A 发送单聊和群聊消息。B 登录同一账号。 | 重新登录后可见范围符合产品历史策略，消息进入正确账号和会话。 |
| IM-OFF-R06 | P0 | 无历史的首次会话 | B 无该单聊历史。B 离线后，A 向 B 首次发送消息。B 恢复。 | 按规则建立新会话并显示正确头像、名称、摘要及未读状态，详情中有对应首条消息。 |
| IM-OFF-R07 | P1 | 网络切换 | B 在 Wi‑Fi 与移动网络之间切换，分别覆盖两个方向。A 在已确认的断线窗口发送。 | 网络稳定后完成补收。切换前、断线中、恢复后的消息均按会话顺序可见。 |
| IM-OFF-R08 | P0 | 弱网反复断连 | 同步中反复断开、恢复 B 的网络。A 持续发带标记的消息，最终恢复稳定网络。 | B 能继续同步且无漏收、重复或永久加载。旧消息补齐后，新消息仍可实时接收。 |
| IM-OFF-R09 | P1 | 同步过程中退出 App | B 恢复后，在确认同步或分页尚未结束时结束 App，再启动。 | 已保存消息保留，未保存消息继续补齐。同一消息最终只出现一次。 |
| IM-OFF-R10 | P1 | 清缓存、重装与升级 | 分别用独立样本在 B 清缓存、重装后重新登录，以及由受支持旧版升级后验证。 | 清缓存、重装后的可见历史符合产品规则。升级后原可见记录仍可用，新增离线消息可以补收。 |
| IM-OFF-R11 | P1 | 登录凭证过期 | B 离线期间使登录凭证过期。A 发消息后，B 恢复网络并按提示重新鉴权。 | 未鉴权时无法取得会话数据。鉴权恢复后，B 能按历史策略同步有权访问的消息。 |
| IM-OFF-R12 | P2 | 空同步与连续启动 | B 离线期间不发新消息。B 恢复后反复进入会话、刷新及冷启动。 | 原有会话内容和未读数保持正确，无新增气泡或错误提醒。 |

## 4. 消息一致性、未读与权限

| 编号 | 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- | --- |
| IM-OFF-C01 | P0 | 单会话混发 | B 离线时，A 按顺序混发文本、表情、图片、语音、视频和文件，包含两条内容相同但分别发送的消息。 | 实际消息集合与发送成功清单一致。独立发送的同内容消息都保留，顺序按会话规则展示。 |
| IM-OFF-C02 | P0 | 多会话并发 | B 离线时，A、C 分别在两个单聊和测试群发消息，群内同时有多个发送人。 | 各会话消息、发送人和摘要匹配，无串会话。每个会话内部顺序符合服务端记录或产品排序规则。 |
| IM-OFF-C03 | P0 | 分页边界与多页 | 若可获取单页上限 N，分别准备 N−1、N、N+1、超过两页四组数据。恢复后验证到最早待补消息。 | 页首和页尾无缺口或重复。允许按需加载历史的版本，可按规则继续加载并找到边界两侧的消息。 |
| IM-OFF-C04 | P0 | 离线补收与实时投递重叠 | B 开始同步时继续向该会话发新消息。用可控环境重复投递同一消息，或用日志确认重复投递实际发生。 | 同一消息 ID 只显示一次，也只按一条计入未读。实时新消息和补收消息均完整可见。 |
| IM-OFF-C05 | P0 | 同步失败后重试 | 在授权测试环境让某一批同步请求超时或返回可重试错误，恢复后观察后续同步。 | 失败批次不会被跳过。重试后缺失消息补齐，已有消息不重复，界面可从失败状态恢复。 |
| IM-OFF-C06 | P0 | 发送失败不生成离线消息 | B 离线时，让 A 分别发一条确认未被服务端接受的消息和一条成功消息。B 恢复。 | B 只收到成功消息。发送结果未知时先查服务端状态，再判定该消息是否应出现在 B 端。 |
| IM-OFF-C07 | P0 | 未读数和会话摘要 | B 在会话列表停留并记录各会话未读基线。离线期间向多个会话发送已知数量的消息。恢复后先看列表，再只打开一个会话。 | 摘要和排序按规则更新。各会话未读增量与可计数消息一致，打开一个会话不误清其他会话未读。 |
| IM-OFF-C08 | P0 | 离线期间发送后撤回 | B 离线时，A 分别发送并撤回文本、媒体，再发送一条正常消息。增加 B 离线前已缓存原消息的对照。 | 恢复后原消息按撤回规则失效或显示提示，旧内容不会在二次同步后重新出现，其他消息正常。 |
| IM-OFF-C09 | P1 | 发送方本地删除 | A 成功发送消息后，仅从 A 本地删除。B 在离线期间尚未收到该消息。 | 对仅影响本端的删除操作，B 恢复后仍按规则收到该消息。 |
| IM-OFF-C10 | P0 | 群成员资格变化 | 分开执行离线期间入群、主动退群、被移除和群解散。A 在成员变化前后发送可区分消息。 | B 只看到产品定义的可访问历史和事件。失去权限后的消息及媒体不能通过会话或旧入口越权获取。 |
| IM-OFF-C11 | P1 | 好友关系与黑名单变化 | B 离线期间，分别改变好友关系、黑名单状态。A 在变更前后尝试发送并记录服务端结果。 | 恢复后消息可见范围符合对应关系规则。被拒绝的发送不会生成接收方消息。 |
| IM-OFF-C12 | P0 | 账号切换与隔离 | A 向离线的 B 发送消息。B 所在设备切换到 C 后查看会话和旧通知入口，再切回 B。 | C 看不到 B 的消息正文、摘要、附件或未读数据。切回 B 后只同步 B 有权访问的会话。 |
| IM-OFF-C13 | P1 | 同账号多端读状态 | B1 离线，B2 在线接收并阅读。B1 恢复，检查消息和未读；产品提供对端已读回执时同时检查 A 端。 | 两端可见消息符合历史同步策略。未读和已读回执符合跨端规则，单纯收到消息不会被记成主动已读。 |
| IM-OFF-C14 | P1 | 保留期限边界 | 若产品有保留期限 T，分别准备接近 T、达到 T、超过 T 的测试数据，恢复后查对应消息。 | 各边界符合已确认的保留和历史策略。过期数据按规则处理，后续正常消息仍能同步。 |

## 5. 系统通知

以下场景单独记录通知是否出现、通知内容和点击结果。每条用例同时确认 App 内同步结果，避免用通知栏代替聊天记录验收。

| 编号 | 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- | --- |
| IM-OFF-P01 | P0 | 正常离线推送 | B 设备联网，IM 实时连接断开，系统和 App 通知开启。A 分别发送单聊及群聊消息。 | 符合策略的消息产生对应通知。发送人、会话及摘要正确，进入 App 后能同步对应消息。 |
| IM-OFF-P02 | P1 | 按类型核对通知摘要 | 分别发送文本、图片、语音、视频、文件、表情和群 `@`，其余类型按已定义通知规则抽查。 | 通知摘要与实际类型匹配，显示范围符合预览设置，不出现原始数据或错误类型。 |
| IM-OFF-P03 | P0 | 系统通知权限关闭 | 关闭 B 的系统通知权限，保持设备联网且 IM 连接断开。A 发送消息，B 手动打开 App。 | 无该 App 的系统通知。B 进入 App 后能补齐消息，会话和未读状态正确。 |
| IM-OFF-P04 | P1 | App 通知关闭与会话免打扰 | 分别关闭 App 消息通知、开启单聊免打扰和开启群免打扰；群场景分别发普通消息和 `@B`。 | 通知、声音、角标及 `@` 例外按配置生效。允许接收的消息正常补收。 |

## 7. 回归顺序与失败证据

| 执行项 | 口径 |
